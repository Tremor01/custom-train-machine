# Серверное обучение и распознавание

## Требования

- Node.js 20+ и npm.
- Linux VPS для production (рекомендуемая платформа `@tensorflow/tfjs-node`); старт без GPU, GPU/CUDA не требуется.
- Диск для приложения, базовой MobileNet и данных в `DATA_DIR` (по умолчанию `./data`).
- Один активный пользователь/job. На сервере лимиты: до 20 классов, до 200 изображений на класс, до 6 MiB на изображение и 64 MiB суммарно.

## Установка и запуск

```sh
npm ci
npm run build
NODE_ENV=production HOST=0.0.0.0 PORT=3000 npm run server
```

API не имеет встроенной авторизации. Любой клиент, который может соединиться с портом, сможет загружать данные для обучения и отправлять кадры на предсказание. Не публикуйте API напрямую в интернет; ограничьте доступ firewall/VPN или используйте внешний authenticated reverse proxy. Vite разработка использует `npm run dev`.

## Docker Compose с HTTPS и sslip.io

В репозитории Caddy настроен на `48-102-168-193.sslip.io`, которое резолвится в публичный IPv4 `48.102.168.193`. Проверьте, что IP VPS статический, DNS разрешает это имя в него, а входящие TCP порты 80 и 443 разрешены в firewall/security group и не заняты другим веб-сервером. Запустите `docker compose up -d --build`; Caddy автоматически запросит и продлит сертификат Let's Encrypt и проксирует HTTPS в контейнер приложения. Откройте `https://48-102-168-193.sslip.io`. Порт приложения 3000 опубликован только на `127.0.0.1`; сертификат и состояние Caddy хранятся в volumes `caddy-data` и `caddy-config`.

Если Caddy не получает сертификат, проверьте `docker compose logs -f caddy`, DNS и доступность портов 80/443 снаружи. При CGNAT, закрытых портах или не совпадающем IP HTTP-01 проверка не пройдёт. Поскольку встроенной авторизации API нет, настраивайте публичный доступ только осознанно; сам HTTPS шифрует трафик, но не ограничивает пользователей.

## Режимы

В обучении файлы отправляются на сервер multipart-загрузкой. Сервер извлекает MobileNetV2 признаки и обучает Dense классификатор в worker thread; браузер получает статус job. После обучения можно выбрать локальную обработку камеры в браузере (видео не покидает устройство) или серверную (JPEG кадры отправляются на API по одному, без накопления очереди).

## Хранение и безопасность

`DATA_DIR/models` хранит версионированные классификаторы и активную версию, `DATA_DIR/jobs` — временные входные изображения. Предоставьте доступ к этой папке только учётной записи процесса и включите её в резервное копирование, если нужно сохранять модель между перезапусками. Удаляйте старые версии/проектные данные согласно вашей политике хранения. Так как авторизации нет, сетевое ограничение доступа обязательно.

Кадры камеры не сохраняются: серверное распознавание принимает кадр в памяти и возвращает вероятности. Данные обучения сохраняются только как временные файлы до завершения job; готовый classifier и метаданные остаются в DATA_DIR.

## Производительность

Установка `@tensorflow/tfjs-node` может требовать скачивания native TensorFlow binary и поддерживаемую платформу/архитектуру. CPU — первый режим для проверки. Фактическая скорость зависит от VPS CPU, Node/TensorFlow native binding, размера данных и сетевого RTT. Измеряйте отдельно загрузку/декодирование, MobileNet extraction, обучение, client inference, server inference и RTT; цифры FPS не гарантируются без замера на целевой конфигурации.

Приложение сохраняет head как TensorFlow.js LayersModel и отдаёт его вместе с манифестом; базовый MobileNet extractor остаётся отдельным артефактом в приложении. Обе стороны должны соответствовать манифесту preprocessing.
